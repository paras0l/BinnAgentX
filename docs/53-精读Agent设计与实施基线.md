# 精读 Agent 设计与实施基线

> 状态：实施基线 v1.0
>
> 日期：2026-08-04
>
> 适用范围：语境实验室“整句精读”临时任务；是 `docs/52-语境实验室精读模式设计与实施基线.md` 的增量设计。
>
> 证据边界：Agent 输出是带原文锚点的学习建议，不是唯一标准答案。自动化测试证明契约、校验、降级和交互链路成立，不证明句法判断绝对正确或学习效果已经提升。

## 1. 目标与归属

精读 Agent 在用户完成整句翻译和至少一处自主成分标记后，联合分析三类输入：

1. 原句；
2. 用户整句翻译；
3. 用户句子成分标记。

它继续属于现有旅程：

`选中原文 → 仍没看懂 → 整句精读临时任务 → 用户翻译/标记 → 查看识别内容 → 点击结果继续追问`

不新增独立 Agent 页面、聊天工作区、任务聚合或完成状态机。初次分析与追问都复用：

- 现有 `POST /learner/v1/tasks/{task_id}/annotations/analyze`；
- 现有 `reading.analyze_selection.v1` 工具权限、模型预算、请求缓存、调用账本和错误降级；
- 现有精读临时任务和浏览器会话恢复；
- 现有内容版本、段落范围和原文哈希校验。

## 2. 教学原则

- **先尝试再解释**：翻译非空且至少有一处自主标记后才运行 Agent。
- **先指出差异再给结论**：解释用户理解与候选分析在哪一处对齐、遗漏或角色不同。
- **不把候选当标准答案**：未经冻结句法 Provider 验证的结果统一称为“候选分析”。
- **不凑卡片**：没有可靠原文锚点的知识卡片不返回、不展示。
- **追问不代做**：回答当前句子的结构、语义和判断依据，不回答主任务选择题，不扩展为全文代读。
- **一次追问只围绕一个对象**：点击哪张卡，就把该卡及原句作为最小上下文，不把整个页面重新塞进提示词。

## 3. 初次分析输出

### 3.1 翻译诊断

展示为“你的翻译 vs 候选译法”，包含：

- `summary`：一句话总评；
- `strengths`：用户已经处理正确或方向合理的点，允许为空；
- `issues`：最多四项具体差异，允许为空；
- 每项差异包含原文锚点 `source_quote`、用户译文片段 `learner_excerpt`（可空）、解释 `explanation` 和修改方向 `suggestion`；
- `reference_translation` 继续复用既有 `translation` 字段，不覆盖用户输入。

翻译诊断不得只给“对/错”或分数；必须说明差异来自词义、修饰范围、逻辑关系、省略补足或语气中的哪一类。

### 3.2 对应解释

解释不是单独凑出的固定栏目，而是以下内容的共同表现形式：

- 翻译差异解释；
- 句子成分候选的 `explanation`；
- 语法、搭配、熟词生义的锚点解释；
- Agent 的 `diagnosis`、`breakdown` 和 `next_check`。

所有可见解释块都可以点击继续追问。

### 3.3 知识卡片

Agent 只在本句确实出现且可锚定时返回知识卡片：

```text
category: grammar | collocation | vocabulary | translation
title: 学习者可识别的短标题
source_quote: 原句逐字锚点
rule: 一句话规则或语境义
explanation: 这条知识怎样作用于本句
check_question: 一个不泄露主任务答案的自检问题
```

知识卡片与既有 `grammar_points`、`collocations`、`familiar_word_senses` 兼容：旧字段继续用于低版本响应，`knowledge_cards` 是更适合交互和追问的结构化表现。无可靠项目时为空数组。

### 3.4 句子成分参考划分

Agent 返回带句内偏移的可靠候选成分，服务端完成原文范围校验。前端只展示一遍完整原句，并在原句上用用户配置的线型标出标准划分，不再生成逐项“我的标记 / 候选标记 / 差异状态”对照表。

有包含关系的候选成分按外层、较长范围优先展示，避免一行文字重复或标记重叠；被折叠的内层成分仍可由知识卡片解释。每个可见标记都是可聚焦按钮，悬停或键盘聚焦时出现“成分名称 · 追问”入口，点击后围绕该成分继续提问。

## 4. 可点击追问

### 4.1 可点击对象

- 翻译诊断总评与每条差异；
- 每张知识卡片；
- 参考划分中的每个成分标记；
- 语法、搭配、熟词生义等兼容解释项。

点击后在当前精读临时任务内展开轻量追问区，不跳转、不打开全屏聊天页。追问区包含：

- 当前追问对象摘要；
- 2–3 个对象相关的快捷问题；
- 自由输入框；
- 回答、原文依据和下一步可追问建议；
- 关闭追问区和重试动作。

快捷问题按对象类型提供，例如：

- 翻译差异：“为什么这里不能这样译？”“如何判断修饰范围？”
- 知识卡片：“这个规则在本句如何成立？”“换个简单例句说明”
- 成分划分：“这个成分判断依据是什么？”“如何先找谓语再判断？”

### 4.2 请求契约

追问仍调用同一分析 API，并在精读上下文上增加可选 `follow_up`：

```json
{
  "analysis_mode": "intensive_reading",
  "learner_translation": "...",
  "learner_component_marks": [],
  "follow_up": {
    "target_kind": "translation_issue | knowledge_card | component_comparison | explanation",
    "target_label": "修饰范围",
    "target_content": "当前卡片或对比的最小必要内容",
    "question": "为什么这里不能这样译？"
  }
}
```

响应在既有分析结构上增加可空 `follow_up_answer`：

```text
answer: 直接回答当前问题，最多 800 字
evidence_quotes: 1–3 个逐字来自原句的依据
next_questions: 0–3 个继续追问建议
```

没有 `follow_up` 时，`follow_up_answer` 必须为空；存在 `follow_up` 时，模型响应必须包含回答，否则按既有降级链路返回保守回答或失败状态。所有 `evidence_quotes` 必须通过原句逐字校验。

### 4.3 会话状态

每个精读任务保存自己的追问记录：

```text
idle → asking → answered
             ↘ failed → retry
```

记录包含追问对象、问题、回答、依据、建议问题和状态。切换临时任务、返回全文或切换学习功能导航后仍随精读会话恢复；内容版本变化后不得复用。

v1 不实现跨设备长期对话，不把追问记录写成主任务完成证据。

## 5. 模型与确定性责任边界

### 5.1 Agent 负责

- 联合阅读原句、用户翻译和用户标记；
- 生成翻译诊断、候选成分、锚点解释和知识卡片；
- 回答聚焦单个组件的后续问题；
- 在证据不足时返回空数组或保守说明。

### 5.2 确定性代码负责

- 内容版本、段落、偏移、哈希和所有原文锚点校验；
- 用户标记合法性；
- 候选成分的范围合法性、排序和重叠折叠；
- 最大项数、字段长度、枚举和额外字段拒绝；
- 预算、超时、缓存、调用账本、降级和公开原因码；
- 不把分析或追问计入主任务答案与完成证据。

## 6. 降级策略

- 初次分析失败：保留用户翻译与标记，展示既有降级原因，并在右侧提供“重新调用精读 Agent”以复用原分析链路刷新存量降级结果。
- 只有旧版有效字段：继续展示参考译文和已有相关项，不伪造翻译诊断、知识卡片或参考划分。
- 追问模型不可用：保留问题，显示公开错误或基于当前卡片的保守回答；不清空初次分析。
- 某张知识卡片锚点无效：仅过滤该卡，不让整份有效响应失败。
- 候选成分锚点无效：仅过滤该候选，不影响其余可靠成分的参考划分。

精读分析使用独立的调用次数、费用、输出长度和超时预算，不与本步其他 Agent 共用过低的三次调用上限。默认使用已验证可用的 `deepseek-chat`；模型名、密钥或供应商额度异常时应记录可诊断的拒绝原因，修复配置后的新模型变体不得命中旧降级缓存。

## 7. 视觉与交互

- 初次分析结果沿用临时任务内容区，不再套一层大卡片页面。
- 右侧临时任务只承载翻译输入、翻译诊断、候选译法及其追问；不重复展示知识卡片、语法/搭配/词义和成分参考划分。
- 左侧整句精读区在原句与自主标记下方承载知识卡片、语法/搭配/词义、成分参考划分、降级说明及这些内容的追问记录。
- 用户译文只保留在右侧输入区，不在诊断内重复；翻译诊断展示候选译法、总体判断和相关问题。
- 成分参考划分紧贴在左侧原句正下方，形成上下对照，只用轻分隔线与“参考划分”标签区分，不再套卡片或句子内框；只展示一遍正确标注的完整句子，悬停或键盘聚焦某个标记时显示追问入口。
- 知识卡片在左侧紧凑排列，整卡可点击且有明确按钮语义、悬停和键盘焦点。
- 追问区作为对应栏位内的内联抽屉：翻译类留在右侧，其他精读分析留在左侧；使用当前皮肤 token，不切换皮肤、不删除角色装饰。
- 加载只发生在追问区，不遮住原句、翻译诊断和既有回答。

## 8. 可访问性

- 所有可追问组件使用真实 `button` 或包含明确按钮，不用只有点击事件的 `div`；
- 成分标记具有包含成分名称和原文的无障碍名称，线型不是唯一线索；
- 追问打开后焦点移到问题输入框，关闭后返回触发组件；
- 回答完成由 `role="status"` 播报，失败由 `role="alert"` 播报；
- 快捷问题与自由输入可完全使用键盘操作。

## 9. 实施切片

1. 扩展模型输出、请求和 API View，保持旧响应兼容；
2. 强化精读 Prompt 和输出锚点校验；
3. 实现参考划分的范围整理与单元测试；
4. 扩展精读会话的追问记录和浏览器会话恢复；
5. 实现翻译诊断、知识卡片、参考划分与内联追问组件；
6. 增加模型网关、API、前端组件与浏览器端到端测试。

## 10. 验收标准

- Agent 请求同时包含原句、用户翻译和合法成分标记；
- 初次结果可展示翻译诊断、非空知识卡片和正确标注的完整句子参考划分；
- 参考划分不展示逐项差异表，且每个可见成分能通过悬停或键盘聚焦进入追问；
- 翻译诊断、知识卡片、参考划分和兼容解释项均可点击追问；
- 追问只更新当前精读任务，不重跑或清空主任务状态；
- 追问回答包含通过校验的原文依据，或明确说明当前没有足够依据；
- 返回全文、切换临时任务、切换学习功能导航后，分析和追问记录仍可恢复；
- 普通选区分析与普通临时任务行为不变；
- 远程模型关闭、超时、预算耗尽和无可靠锚点均有确定性降级；
- 类型检查、Python 单元/集成测试、前端测试、主题契约、生产构建和关键浏览器流程通过。
