# 阅读写回资产内容去噪方案

## 1. 归属与接入点

阅读标记、H1–H4 分层帮助和“随时记”已经统一进入
`POST /learner/v1/assets`，再通过既有 outbox、资产导出器和 Obsidian
插件完成写回。本增量不建立新的记忆库或同步流程，而是在这个统一写入边界对
`initial_content` 做保守去噪；后续导出、重试、回执、证据状态和冲突处理均沿用原链路。

## 2. 近期方案调研

截至 2026 年 7 月，相关研究的共同方向已经从“把完整交互全部存入长期记忆”转向：

- **显式写入决策**：AgeMem 把 store、update、summarize、discard 等记忆操作纳入策略；
  Memory-R1 使用 ADD、UPDATE、DELETE、NOOP 结构化操作，说明“不写入”本身应是一等决策。
- **在线轻处理、离线巩固**：LightMem 将在线检索/写入与离线长期巩固拆开，在线阶段控制预算，
  离线阶段再抽象可复用证据。
- **选择性存储与来源保留**：MemORAI 组合选择性过滤、双层压缩和 turn-level provenance，
  避免压缩后无法追溯事实来源。
- **细粒度最小充分信息**：FineFilter 在句子级提取、重排并截断到最少充分线索。虽然它面向
  RAG 检索，但“先保召回，再去冗余”的原则同样适用于资产写入。
- **错误记忆会放大**：ACL 2026 的经验研究表明，相似任务会强烈复用历史经验；错误或错配经验
  会继续传播，因此写入质量门比单纯扩大记忆容量更重要。

## 3. 本次采用的策略

当前资产正文包含学习者原话、精确原文引用和 Agent 分层帮助，贸然让模型在线摘要会改变措辞，
也可能把“提示过”误写成“已经独立掌握”。因此先落地确定性、可回放、低损失的写入门：

1. 统一换行、Unicode 和不可见控制字符；
2. 保留引用、标签、顺序和原始措辞；
3. 删除阅读界面自动附加、但不承载知识的精确话术块；
4. 对忽略 Markdown 引用/列表前缀后的完全重复块去重；
5. 对连续重复行去重并压缩空白；
6. 去噪后无有效内容时停止正文导出，并留下 `content_filtered_noop` 可审计状态。

去噪集中在 API 写入边界，而不是分别散落到标记、提示和随手笔记组件中，保证所有既有入口最终
进入同一条链路。规则只做精确匹配，不做模糊语义合并，避免误删相似但含义不同的例句。

## 4. 已实现的增强链路

### 4.1 结构化采集

阅读标记、分层帮助和随手笔记不再只发送扁平的 `content + note`，而是发送
`learning-asset-capture/v1`：

- `source_quote`
- `learner_interpretation`
- `agent_hint`（保留 H1–H4）
- `diagnosis`
- `reusable_rule`
- `example`
- `next_check`

每个 segment 带稳定 ID、`source / learner / agent` 来源；服务端验证提示等级只能属于 Agent
提示。旧客户端的 `initial_content` 仍兼容。

### 4.2 异步写入门

结构化资产的 outbox 初始状态为 `denoising`，Obsidian 插件只读取 `pending`，因此不会抢先拿到
未去噪正文。资产导出 Worker 执行 `KEEP / SPLIT / NOOP / REVIEW` 后才把消息转回既有导出链路。

远程模型只能返回保留的 segment ID，不能生成正文。服务端有两层硬约束：

- Agent 提示不能被模型升级为独立掌握；
- 模型不能静默 `NOOP` 掉仍有有效内容的学习者原话，这类决策降级为 `REVIEW`。

模型超时或不可用时使用确定性投影；调用通过既有 invocation ledger 保证幂等和可恢复。

### 4.3 复用知识组织 Worker

结构化 capture 会以不可变 `knowledge_source_record` 和 payload 进入已有 LangGraph
知识组织流程，不建立第二套状态机。原子抽取继续要求精确 source span。确定性降级只允许把
`origin=learner` 的解释、规则或例句提升为候选，Agent 提示单独存在时不会生成知识候选。

### 4.4 Top-K 与变更决策

现有匹配从“精确 canonical key 或标题命中一条”升级为：

1. 同一学习者、同一资产类型粗召回；
2. canonical key 精确命中优先；
3. 标题与 claim 的 token Jaccard / sequence similarity 重排；
4. 保留最多四条候选进入人工可审计提案。

后续仍沿用既有 `CREATE / LINK / MERGE / SUPERSEDE / MARK_CONFLICT / DISCARD / DEFER`，
分别覆盖 ADD、NOOP、合并和冲突语义。破坏性变更保留 expected version 和人工复核要求。

### 4.5 证据与最终投影

结构化新资产立即进入 `pending_validation` 并安排复习，但“保存了一条提示”本身不会伪造掌握
证据。之后的独立理解、提示后输出和延迟迁移继续由既有 evidence projector 更新
`hinted_usable / independently_usable / delayed_stable`。

知识冲突现在同时写入不可变 `conflict` evidence，再投影为 `evidence_conflict`，而不是只修改
索引状态。Obsidian 接收到的是写入门渲染后的分节投影或经过人工批准的版本化补丁；原始
segment 来源保存在知识 source payload 中。

### 4.6 原始副本隔离与效果对照

结构化 capture 的去噪前副本只写入不可变 `knowledge_source_payloads`；新增的
`learning_asset_content_projections` 只保存去噪后的正文、决策、原因码、保留 segment 和内容
哈希。两层通过 `source_record_id` 关联，但不在同一记录或同一 outbox payload 中混存：

- outbox 在去噪前只持有 source reference；
- 写入门从原始层读取，完成后将投影写入独立表；
- outbox 随后只携带去噪投影进入 Obsidian 导出；
- 处理完成后仍可分别审计原始副本和投影，不依赖 outbox 充当内容数据库。

学习者可通过资产页“对照去噪”按需读取本人资产的双栏视图。接口返回去噪决策、原因码、保留和
移除的 segment、前后字符数与缩减比例；其他学习者的资产仍由 `_owned_asset` 拒绝访问。

## 5. 尚未引入的能力

当前 Top-K 使用模型抽取出的语义 canonical key 加本地词法重排，没有引入 embedding
基础设施或自动删除。后续只有在离线评测证明误合并率可接受后，再考虑向现有候选匹配器增加
向量召回或 cross-encoder；原始证据仍不得覆盖。
