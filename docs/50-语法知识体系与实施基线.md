# 语法知识体系与实施基线

> 状态：v1 首个纵向切片工程验收完成；正式质量发布受 G-04/G-05/G-06/G-08 阻断  
> 日期：2026-07-28  
> 适用范围：个性化内容目标、句法分析、语法挑战、知识整理、学习证据、语境实验室与表达实验室  
> 关联基线：`docs/48-Agent内容质量与双实验室闭环升级基线.md`、`docs/49-Agent升级决策门台账.md`

## 1. 核心决策

项目以版本化语法构式 `GrammarConstruction` 作为统一语法知识单元，以不可变
`GrammarEvidence` 作为能力状态的唯一事实来源。

语法体系不是供学习者打卡的孤立规则树，而是现有学习链路后台共享的：

```text
构式目录
  → 教学目标
  → 阅读材料与句法候选
  → 语法挑战和标注
  → 构式级证据
  → 表达迁移
  → 延迟复核
```

新增能力必须进入既有 `matched_reading → micro_expression → wrap_up`，不得创建
平行语法工作区、第二套训练状态机或独立“语法课程中心”。

## 2. 构式定义

每个构式必须同时描述：

1. `form`：可观察形式、槽位和角色；
2. `meaning`：该形式表达的语义关系；
3. `use`：在句子、篇章或交际中的功能；
4. `constraints`：适用条件、禁用组合和歧义边界；
5. `relations`：前置、变体、对比、易混和考试能力映射；
6. `parser_signatures`：解析器可提供的候选证据，不作为教学真值；
7. `can_do_outcomes`：可通过任务观察的行为结果。

稳定 ID 使用带版本的层级命名，例如：

```text
clause.adverbial.concession.although.v1
```

CEFR、English Grammar Profile 和考试要求只作为外部映射或等级先验，不能成为构式
主键。依存关系和模型标签只能作为候选证据，不能直接写成已确认知识。

## 3. 图谱结构

构式目录使用带类型关系的有向图，不强迫全部知识落入一棵树。首批关系包括：

```text
IS_A
REQUIRES
VARIANT_OF
CONTRASTS_WITH
COMMONLY_CONFUSED_WITH
REALIZES_FUNCTION
SUPPORTS_EXAM_SKILL
```

目录发布必须满足：

- 构式 ID 和别名全局唯一；
- 所有关系目标存在；
- `REQUIRES` 不形成循环；
- 每个节点具有 form、meaning、use 和至少一个可观察结果；
- 目录版本与证据中的构式版本可回放；
- 旧自由标签只能通过显式兼容映射进入目录，不能继续扩散。

## 4. 能力与证据模型

“接触—识别—拆解—改写—迁移—稳定”保留为面向用户的概括。后台状态按以下维度
分别投影：

| 维度 | 首批取值 |
|---|---|
| 能力面 `facet` | `form / meaning / use` |
| 模态 `modality` | `receptive / productive` |
| 独立度 | 看答案、提示支持、独立完成 |
| 语境 | 原语境、换词、换主题、延迟陌生语境 |
| 结果 | 尝试、成功、失败、冲突、待验证 |

首批晋级规则：

1. 展示内容或揭示答案只形成 `exposure`，不得形成独立掌握；
2. 有提示纠错形成 `supported_recognition`；
3. 无提示纠错形成 `independent_recognition`；
4. 表达任务只要尚未验证目标构式，就只能形成
   `production_attempt_unverified`；
5. 独立证据在不同语境、间隔达到策略要求后，才可形成
   `delayed_transfer`；
6. 识别与产出、form/meaning/use 分别保存，不互相冒充；
7. 总体语法等级只能从构式状态汇总，不能用单题 `resolved` 比例直接代表能力。

具体间隔和晋级阈值是待真实学习数据校准的产品策略，不作为语言学习研究事实写死。

## 5. 与现有领域的集成

### 5.1 个性化内容

- `TargetGrammarStructure` 必须引用 `construction_id`、目录版本和目标能力面；
- 模型输出不得创建自由 `structure_key`；
- `GrammarAnalysisArtifact` 保存构式 ID、角色跨度、form/meaning/use、解析证据、
  置信度和审核状态；
- 完整材料审核继续复用现有 LangGraph interrupt 和开发者控制入口。

### 5.2 语法挑战

- 每道挑战必须声明构式 ID、版本和测试能力面；
- 揭示答案和独立纠正使用不同的 `resolution_kind`；
- 题目完成状态继续由既有任务聚合管理；
- 构式证据从挑战回执追加，不能由 UI 或模型直接修改掌握状态。

### 5.3 知识整理

- grammar 候选必须解析到目录中的构式 ID；
- 旧标签可以通过显式别名映射；
- 无法解析的候选进入 `DEFER/needs_review`，不得创建新的自由语法主键；
- 已解析候选仍需沿现有人工审核、知识提案、资产提交和 Outbox 链路处理。

### 5.4 双实验室

- 阅读目标、语法分析、挑战和表达迁移共享同一个构式 ID；
- 阅读证据只能提升 receptive 状态；
- 表达任务完成但未验证目标形式时，不提升 productive 掌握；
- 后续加入表达验证器或人工证据后，再形成独立产出与延迟迁移证据。

## 6. 首个纵向切片

首个必须跑通的节点是：

```text
clause.adverbial.concession.although.v1
```

验收场景：

1. 目标包选择让步构式的 meaning/use；
2. 阅读文章包含可定位的 `Although + finite clause, main clause`；
3. 语法分析引用正式构式并保存主从句角色证据；
4. 挑战测试连接词所表达的让步/反预期关系；
5. 揭示答案不形成独立识别证据；
6. 无提示纠正形成 receptive/meaning 的独立证据；
7. 表达任务在新主题中要求使用同一让步功能；
8. 未验证表达只记录待验证产出，不宣称 productive 掌握；
9. 知识整理中的 `concession_clause`、`grammar:concession:although` 等旧标签解析到
   同一 ID；
10. 总体语法评估读取构式状态汇总，而不是把所有 `resolved` 当成同一种能力。

## 7. 实施任务

### T-01 构式目录与验证器

- 建立版本化目录契约和运行时加载器；
- 建立首批高价值构式、旧标签别名和关系；
- 校验唯一性、关系目标和前置循环。

### T-02 内容与分析契约

- 替换新路径中的自由 `structure_key`；
- 增加构式角色、form/meaning/use 和目标能力面；
- 保留旧数据只读兼容映射。

### T-03 挑战与持久化

- 内容包和静态内容都绑定构式；
- 持久化构式、能力面和 `resolution_kind`；
- 修正“揭示答案等于独立解答”的历史语义。

### T-04 构式证据与状态投影

- 建立不可变构式证据和可重建状态；
- 接入现有运行完成回写；
- 分离 receptive/productive 和 form/meaning/use；
- 由构式状态派生总体语法维度。

### T-05 知识整理接入

- grammar 候选先解析目录；
- 未解析候选显式 DEFER；
- 复用现有人工审核和资产提交链路。

### T-06 双实验室闭环

- 迁移契约同时携带篇章动作和构式目标；
- 表达侧只记录其实际获得的证据等级；
- 验证同一构式 ID 可贯穿阅读、挑战、表达和复习。

### T-07 测试与人工验收

- 目录契约、关系、别名和循环测试；
- 旧标签兼容和自由标签拒绝测试；
- 答案揭示不晋级测试；
- 提示/独立/延迟证据投影测试；
- 内容生成、知识整理和双实验室集成回归；
- 对首个让步构式逐项人工审核 form、meaning、use、对比、任务和证据语义。

## 8. 完成定义

只有同时满足下列条件，首个语法体系切片才可标记工程验收完成：

- 新产物 100% 引用有效构式 ID 和版本；
- 同一构式 ID 贯穿目标、分析、挑战、整理、证据和表达迁移；
- 揭示答案、提示纠错和独立纠错产生不同证据；
- 阅读证据不会提升 productive 状态；
- 未验证表达不会被计为独立产出；
- 状态可由不可变证据确定性重建且重放不重复；
- 旧自由标签有明确兼容窗口，未知标签被拒绝或 DEFER；
- 静态检查、单元测试、集成测试和人工语言审核全部通过；
- 未关闭的解析器、专家金标、正式审核责任和真实环境 Gate 继续显式阻断正式质量
  发布，工程验收不得被描述为教研或生产验收。

## 9. v1 实施证据

2026-07-28 已完成：

1. 发布 17 个首批构式节点、别名兼容表、JSON Schema 和运行时图校验器；
2. 目标包、模型输出、分析产物、挑战和迁移契约统一使用构式 ID；
3. `although` 分析产物保存完整句跨度、让步从句与主句角色、form/meaning/use；
4. 静态 v1 内容保持不可变，通过受审核 `error_type` 兼容映射读取；新生成内容显式
   保存 ID、版本和能力面；
5. 持久化 `resolution_kind`，答案揭示、支持纠错和独立纠错不再混同；
6. 新增不可变 `grammar_learning_evidence` 与可重建
   `learner_grammar_states`；
7. 阅读挑战形成 receptive 证据；表达完成但未验证目标构式时只形成
   `production_attempt_unverified`；
8. 知识整理 grammar 候选统一解析到构式目录，未知标签进入待审核/DEFER；
9. 句法 Provider 的自由标签只生成构式候选，未知标签不会创造知识节点；
10. 总体语法评估改为构式覆盖、稳定和产出状态的派生摘要。

自动验收：

- Python 单元测试：通过；
- 机器契约与内容完整性：通过；
- PostgreSQL 迁移与 37 项集成测试：通过；
- Ruff 与 Mypy：通过；
- 阅读—语法挑战—表达—证据投影端到端集成：通过。

人工语言审核：

- `Although + finite clause, main clause` 的形式边界正确；
- meaning 明确为“承认事实 + 反预期主张”，没有误写成一般转折；
- use 明确连接到 concede-then-assert 篇章动作；
- because、when 对比关系及 although...but 限制表述合理；
- 挑战只替换唯一的 `Although`，不会因超长整句超过作答 API 边界；
- 主从句角色跨度逐字命中原文；
- 未验证表达没有被错误计为 productive 掌握。
