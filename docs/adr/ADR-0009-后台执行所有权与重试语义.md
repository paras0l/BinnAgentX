# ADR-0009：后台执行所有权、检查点与重试语义

> 状态：accepted-for-spike  
> 日期：2026-07-25  
> 决策所有者：项目负责人  
> 适用范围：PostgreSQL Worker、Outbox、LangGraph 工作流、模型调用、人工复核与外部副作用

## 背景

当前后台执行已经具备：

- PostgreSQL `FOR UPDATE SKIP LOCKED` 领取；
- `claimed_by`、短租约和心跳；
- 进程异常后的过期租约回收；
- 业务运行状态和逐步进度；
- Outbox 与外部资产写回；
- 模型调用账本、审计和幂等键。

引入 LangGraph 后，如果业务运行表、Worker 租约、Outbox 和 checkpoint 都能独立决定“任务是否运行、是否完成、是否重试”，会形成多个事实源并造成：

- 同一任务被两个执行器并发恢复；
- checkpoint 显示完成但业务事务未提交；
- 业务表显示运行中但图已等待人工；
- 模型或外部写回被多层重试；
- 取消、恢复和人工审批行为不一致。

需要在引入运行时之前冻结所有权。

## 决策

### 1. 单一事实源

PostgreSQL 业务表继续是用户可见状态、授权、领域事实和完成条件的唯一事实源。

| 数据 | 权威所有者 |
|---|---|
| 学习任务、内容产物、知识资产、证据、版本和发布状态 | 领域业务表 |
| 运行是否排队、执行、待审核、取消、失败或完成 | 对应业务运行表 |
| 待投递命令和跨边界副作用意图 | Outbox |
| 当前 Worker 所有权和短期执行租约 | 业务运行表/投递表 |
| 图节点状态、待执行节点和恢复历史 | LangGraph checkpoint |
| 模型请求、费用占用和响应重放 | 模型调用账本 |
| 跟踪、耗时和技术指标 | Langfuse/OpenTelemetry |

checkpoint 是执行恢复事实，不得直接作为产品状态、学习证据或发布资格。

### 2. 启动协议

启动一个动态图工作流时：

1. API 在一个业务事务中创建或更新业务运行；
2. 同一事务写入 Outbox 启动命令；
3. Worker 领取 Outbox/运行并获得短租约；
4. Worker 使用业务运行 ID 作为 LangGraph `thread_id`；
5. 首节点核对业务运行版本、状态、图名和图版本；
6. 图推进后通过领域命令提交业务事实；
7. 运行完成、中断或失败时更新业务投影并释放租约。

API 不直接在请求事务中执行长图。

### 3. 暂停与恢复

进入人工审核时：

1. 独立领域节点幂等创建或更新审核请求；
2. 图进入 `interrupt()`；
3. Worker 将业务运行标记为 `awaiting_review`；
4. Worker 释放租约并结束本次执行；
5. 审核人通过控制 API 提交带预期版本的决定；
6. API 在同一事务保存审核事实并写入恢复 Outbox；
7. Worker 重新领取后以同一 `thread_id` 调用 `Command(resume=...)`；
8. 图根据审核决定继续、返工或终止。

人工等待期间不保持数据库事务、连接、HTTP 请求或 Worker 槽位。

### 4. 副作用

节点分为三类：

| 类型 | 示例 | 要求 |
|---|---|---|
| 纯节点 | 路由、组装质量报告 | 可安全重跑 |
| 可重放读取/模型节点 | 检索、解析、模型生成 | 使用稳定请求哈希和调用账本复用已完成结果 |
| 业务提交/外部副作用节点 | 发布内容、写资产、Obsidian 回写 | 通过领域事务、Outbox、幂等键和预期版本执行 |

图节点不得直接执行未记账的不可逆外部写入。业务提交与 checkpoint 不能假设原子提交；故障后允许节点重新进入，但领域命令必须返回此前已提交的相同结果。

系统承诺的是“至少一次执行下的业务幂等效果”，不宣称所有代码只执行一次。

### 5. 重试所有权

每类错误只能由一层负责：

| 错误 | 负责层 | 策略 |
|---|---|---|
| 模型网络超时、限流 | 模型网关/调用账本 | 有限指数退避；相同请求键复用完成结果 |
| 输出 Schema 不合格 | PydanticAI/节点 | 小次数本地修复；记录失败 |
| 教学质量缺陷 | LangGraph 质量路由 | 定向返工，不作为异常重试 |
| 数据库序列化冲突 | 领域仓储 | 有限事务重试，重新检查预期版本 |
| Worker 崩溃/租约丢失 | Worker 调度层 | 租约到期后重新投递同一运行 |
| 人工可解决问题 | `interrupt/resume` | 不自动重试 |
| 外部写回失败 | Outbox 消费者 | 有限重试、退避、死信/人工处理 |
| 未知程序错误 | 运行层 | 记录失败并停止；不得无限恢复 |

禁止 LangGraph、PydanticAI、模型网关和 Worker 同时对同一个模型请求各自重试。

### 6. 取消

- 取消是业务命令并形成不可变审计；
- Worker 在节点边界和长调用心跳处检查取消；
- 已提交事实不回滚或删除；
- 尚未发布的产物标记为取消/废弃；
- 正在等待人工的运行可以取消，并使旧恢复令牌失效；
- 外部调用若无法安全中断，允许其完成，但结果不得越过取消版本写入业务状态。

### 7. 检查点生命周期

- checkpoint 使用独立 Schema、最小权限和受控迁移；
- 保存期至少覆盖未完成运行、人工等待期和审计回放窗口；
- 完成运行可按策略归档/压缩，不能先于业务证据保留要求删除；
- checkpoint 清理不得级联删除业务表；
- checkpoint 内容纳入敏感数据分类、备份、恢复和用户删除演练；
- 初始化/升级 checkpointer 表由部署迁移完成，不在每次应用启动时运行。

### 8. DBOS 边界

当前不使用 DBOS 替换 Worker/Outbox，也不让 DBOS 与 LangGraph共同拥有动态图。后续固定任务若采用 DBOS，必须另行 ADR，证明：

- 不复制现有业务运行状态；
- system database 与业务数据库的事务边界清楚；
- workflow ID 与现有幂等键映射稳定；
- DBOS 队列不会与现有 Worker 重复领取同一任务。

## 替代方案

### LangGraph checkpoint 成为运行状态唯一事实源

拒绝。它不能替代领域授权、版本冲突、产品查询、学习证据和业务审计。

### 业务表不保存当前运行投影，只保存最终结果

拒绝。控制舱、取消、审核、用户状态查询和异常治理需要稳定业务投影。

### LangGraph 自己轮询业务任务

拒绝作为首版方案。继续由现有 Worker/Outbox 完成投递和领取，减少第二套队列。

### 立即使用 DBOS 队列替换现有 Worker

暂不采用。当前 Worker 已有租约、心跳、取消和控制舱状态，替换收益尚未通过对照证明。

## 后果

正面影响：

- 业务事实、执行恢复和模型账本边界明确；
- 可以安全处理 checkpoint 与业务事务之间的故障窗口；
- 人工等待不占用执行资源；
- 现有控制舱、Outbox 和领域不变量得到复用；
- LangGraph 可被替换而不丢失业务解释能力。

代价与风险：

- 需要维护业务运行投影与 checkpoint 的一致性对账；
- 节点必须严格区分计算和副作用；
- 所有外部操作需要稳定幂等键；
- 暂停、取消和恢复需要新的 Outbox 主题与控制 API；
- 双层 PostgreSQL 存储增加容量、权限和备份工作。

## 验证证据

转为 `accepted` 前必须通过：

1. API 提交成功但 Worker 启动前崩溃，运行最终可被领取；
2. Worker 启动图后、首个 checkpoint 前崩溃，不重复创建业务运行；
3. checkpoint 成功、业务提交前崩溃，恢复后业务命令只产生一次效果；
4. 业务提交成功、checkpoint 前崩溃，恢复后读取幂等结果并继续；
5. 审核中断前后反复恢复，不重复创建审核请求；
6. 人工等待超过 Worker 租约后不会被当作异常运行抢占；
7. 相同恢复命令重复投递只应用一次审核决定；
8. 取消与节点完成并发时按预期版本得到唯一结果；
9. 模型网关重试次数与 Worker/图重试不会相乘；
10. Outbox 外部写回在重复、乱序和目标暂时离线时保持可恢复；
11. checkpoint 数据库不可用时不把业务运行错误标记为完成；
12. 控制舱能对账业务状态、当前图节点、最近 checkpoint 和待处理命令。

## 回滚方式

- 保留现有 Worker 领取与显式状态机执行入口；
- 停止创建新 LangGraph 运行，旧线程排空或人工终止；
- 由业务运行投影重新投递到显式执行器；
- checkpoint 只读归档以支持审计；
- 不回滚已经提交的业务事实，只更换后续执行器。
